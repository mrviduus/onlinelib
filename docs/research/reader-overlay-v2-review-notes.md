## Крит — обязательно закрыть до выкатки

### 1. Слайс 10 (cleanup legacy reader code) — НЕ пропускать

Без него мы получим не замену overlay-системы, а **вторую** overlay-систему параллельно старой. Tech debt вырастет вместо того, чтобы упасть.

**Задачи:**
- Зафиксировать deadline для слайса 10 прямо сейчас, до начала rollout.
- Составить список legacy-файлов/хуков, которые должны быть удалены (как минимум: старые реализации подсветок, vocab underlines, translation overlay, in-article search highlights — всё, что было до слайсов 4–6).
- Критерий done для слайса 10: `grep` по legacy-именам в `apps/web/src/` и `apps/mobile/src/` возвращает 0 совпадений.
- Не катить слайс 10 в одном PR со слайсом 9 — rollout и cleanup должны быть разделены, иначе в случае отката потеряем cleanup.

### 2. textWalker — юнит-тесты на реальных фикстурах

`textWalker` — место, где живёт половина багов координатной системы (позиционирование highlights / vocab / search). Без регрессионных тестов на реальных главах любой рефактор будет откатываться багрепортами пользователей.

**Задачи:**
- Создать `apps/web/src/lib/__tests__/textWalker.fixtures/` — минимум 20 фикстур из реальных глав БД, на которых раньше воспроизводились баги overlay.
- Приоритет фикстур: главы с `display:none`, ruby-разметкой, MathML, `<span>` внутри слов, soft hyphens (`&shy;`), вложенными блоками, смешанными направлениями (LTR/RTL), таблицами, сносками.
- Для каждой фикстуры — как минимум тест: «выделение от offset A до offset B корректно мапится в DOM range и обратно».
- Покрыть edge cases: выделение через границу блока, выделение внутри воспроизводимого контента (ruby, MathML), пустые текстовые ноды.
- Эти тесты должны бежать в CI и в pre-commit — regression-guard поверх overlay.

### 3. Слайс 9 — метрики, без них не катим

Feature flag без метрик = ощущения, а не данные. Откатывать будем по жалобам, а не по сигналу.

**Задачи (завести ДО включения флага хоть одному пользователю):**
- Метрика 1: **среднее время первой отрисовки главы** (от перехода в ридер до первого `relocate`-эвента). Собирать через OpenTelemetry / отдельный endpoint `/api/telemetry/reader`. Алерт: +20% к baseline.
- Метрика 2: **error rate overlay** — любые unhandled exceptions внутри overlay-скрипта (и в браузере, и в WebView). В Sentry выделить отдельный scope `reader.overlay.v2`. Алерт: error rate > 0.5% сессий.
- Метрика 3: **успешность сохранений** — highlights, vocab words, reading sessions. Сравнение rate до/после включения флага для флаг-on vs флаг-off когорт. Регрессия: drop > 2%.
- Dashboard в Grafana / admin-панели с этими тремя графиками, разбитыми по `overlay_v2: on|off`.
- Rollout-план: 1% → 10% → 50% → 100%, минимум сутки между ступенями, с проверкой метрик перед каждой.
- Документировать rollback procedure (одной командой через admin settings, без передеплоя).

## Важно — слайс 8 (mobile port + E2E)

Грабли, на которые наступают все при WebView-ридере. Проверить КАЖДЫЙ пункт явно:

### 4. Selection API в WebView

iOS (WKWebView) и Android (WebView) по-разному ловят `selectionchange`, `touchend` и контекстное меню.

**Задачи:**
- Написать и протестировать обработчик выделения **отдельно** для iOS и Android.
- На iOS: отключить native callout menu через `-webkit-touch-callout: none` в overlay CSS, иначе всплывает нативное меню поверх вашего тулбара.
- На Android: проверить `ActionMode` — по умолчанию Android WebView показывает системное selection-меню, которое нужно либо переопределять, либо отключать.
- Long-press для вызова словаря/vocab — проверить, что не конфликтует со свайпом навигации между главами и с системным scroll.
- Unit-test на selection edge cases: выделение в одной строке, через несколько строк, через границу параграфа.

### 5. postMessage bridge — throttle `relocate`

Без throttle мост `window.ReactNativeWebView.postMessage` утонет на reading-session heartbeat'ах и scroll-reflow событиях.

**Задачи:**
- Throttle `relocate` эвентов в overlay-скрипте: не чаще 4 раз в секунду (250ms). У reading session heartbeat свой интервал 30 сек — это отдельно.
- Для scroll-based событий — `requestAnimationFrame` + throttle.
- Dedup идентичных payload: если позиция не изменилась — не шлём.
- Замерить частоту сообщений на реальном устройстве (не симуляторе) при быстром пролистывании — должно быть < 20 msg/sec.

### 6. Шрифты внутри WebView

Expo/React Native не делится загруженными шрифтами с WebView автоматически. Если пользователь выбрал шрифт в настройках ридера — в WebView он не появится сам.

**Задачи:**
- В overlay-скрипт инжектить `@font-face` с base64-encoded шрифтами ИЛИ с URL, которые доступны из WebView.
- Вариант получше: шрифты раздаёт backend с long cache-control, WebView фетчит их по URL (работает, если WebView имеет интернет; для офлайн-режима — base64 или `file://` путь к bundled assets).
- Покрыть тестом: смена шрифта в настройках → в WebView применился (скриншот-тест или dom-check).
- Чеклист форматов: woff2 (iOS 10+, Android 5+ — ок), woff (fallback).

### 7. E2E на mobile — обязательный сценарий

Минимум для слайса 8, без этого флаг не открываем:

**Сценарии:**
- Открыть главу → выделить текст → сохранить highlight → перезагрузить главу → highlight на месте.
- Открыть главу → выделить текст → сохранить слово в vocab → перейти в vocab page → слово там есть.
- Открыть главу → in-article search по слову → результаты подсвечены → тап на результат → прыжок к позиции.
- Открыть главу → сделать translation popup → закрыть → overlay не застрял.
- Свайп между главами → позиция сохранилась → вернуться назад → позиция восстановилась.
- TTS: запустить → выделение двигается синхронно → остановить → выделение снимается.

## Важно — проверка scope рефакторинга

### 8. Пагинация и сам рендер — не входят в план?

В слайсах 1–10 не вижу работы над **самой пагинацией / разбивкой на страницы / CFI-эквивалентом**. Overlay — это слой поверх контента, но если баги пользователей про «прыгает прогресс при смене размера шрифта», «теряется позиция после переразбиения главы», «пагинация на мобиле отличается от десктопа» — этот рефактор их не закроет.

**Задачи:**
- Провести аудит топ-20 багов ридера за последние 3 месяца (Sentry + support-канал). Разложить по категориям: (A) overlay/highlights/selection, (B) рендер/пагинация/прогресс, (C) feature-integration (TTS/словарь/vocab), (D) mobile-specific.
- Если категория (B) — меньшинство: план хорош, продолжаем.
- Если (B) — 30%+: нужен отдельный эпик на пагинацию ПОСЛЕ слайса 10, не вместо него. Не расширять текущий план, иначе он никогда не закроется.
- Документировать аудит в `docs/reader-bug-audit-2026-04.md`.

## Nice-to-have

### 9. Дока для будущего себя

После слайса 10 — один короткий ADR:
- Почему overlayer-архитектура, а не готовый движок (foliate-js/epub.js).
- Какие интерфейсы overlay ↔ text walker ↔ book provider.

- Что НЕ надо переписывать, когда вернётся мысль «а давайте возьмём foliate-js».

Живёт в `docs/architecture/reader-overlay-v2.md`. Реально съест 2–3 часа, окупится через год.
