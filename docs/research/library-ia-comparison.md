# Library IA — Readwise Reader vs TextStack

**Author:** Cowork architect agent · **Date:** 2026-04-28 · **Source for:** v3 navigation/IA roadmap

## TL;DR

Readwise Reader has **no public catalog as primary navigation**. Their entire IA is "**your stuff, organized smartly**." Discovery exists (Wisereads) but is buried behind the `+` menu — a tertiary affordance, never primary.

TextStack today inverts this: the marketing site (public domain catalog for SEO) is the primary surface for **logged-in users too**. "My Library" is hidden behind avatar dropdown. This is the structural bug.

**The principle to adopt:** logged-in user lands in their personal workspace; the public catalog stays a discovery surface but loses its claim on primary nav for authenticated users.

---

## Methodology

- **Account:** fresh Readwise Reader signup, 2 starter items, ~30 min hands-on (2026-04-28).
- **Captured:** Inbox, Home, Library/Books, Add menu, Wisereads (curated discovery), full reader view, sidebar nav at every level.
- **Tooling:** Claude in Chrome MCP — direct DOM inspection + screenshots from authenticated session.

- **Out of scope:** mobile apps, paid features, RSS/feed depth.

## Readwise Reader — observed IA principles

### 1. Two top-level personalized surfaces, no public catalog

```
Sidebar (top section):
  Home       ← personalized smart shelves of YOUR content
  Library    ← browseable grid of YOUR content (with sub-categories)
```

Both surfaces are **about you**. Neither is "browse what other people are reading." The closest thing to a public catalog (Wisereads) is reachable only via `+` menu → "Discover new documents", and it's a curation feed, not a marketplace.

### 2. Library has TYPED sub-navigation in left sidebar

```
Library
├─ Articles
├─ Books
├─ Emails
├─ PDFs
├─ Tweets
├─ Videos
├─ Podcasts
└─ Tags
```

**Source/type is a sidebar filter, not separate pages or tabs.** Click "Books" → grid filtered to books only. Click "Library" parent → all types together. Tags is a sibling — filter by tag instead of by type.

### 3. Status as horizontal tabs above the list

```
Center column header: INBOX | LATER | ARCHIVE
```

Three states, every item is in exactly one. **Like email, not like Kindle.** New saves go to Inbox, snooze to Later, finish to Archive. Status is a primary axis of navigation.

### 4. Single `+` entry point for ALL content addition

Click `+` in sidebar header → menu with **10 ways to add content**:

```
URL                                  A
Upload                               U
Email                                
RSS Feed                       Shift A
Twitter List                   Shift A
YouTube Channel                Shift A
─────────────────────────────────────
Configure integrations
Get browser extension
Download apps
─────────────────────────────────────
Discover new documents       ← Wisereads (curated content)
More options
```

**Insight: addition is treated as one concept regardless of method.** There's no "Upload" button in one place and "Add URL" in another. ONE entry, ten ways. Keyboard shortcuts visible right in the menu.

### 5. Three-column layout persistent across views

```
┌──────────┬───────────────────────┬────────────────┐
│ Sidebar  │ Content list          │ Detail panel   │
│ (nav)    │ (paginated/scroll)    │ (info / notebook│
│          │                       │  / chat tabs)  │
└──────────┴───────────────────────┴────────────────┘
```

The right detail panel persists EVERYWHERE — including in reader view, where it sits next to the open document showing metadata, summary (AI-generated by Ghostreader), notebook. **Information about the current item is never more than a glance away.**

### 6. Home = personalized smart shelves, not feed

```
"Welcome Vasyl"

📥 Recently added (Saved in past week, not archived) — default view
   [book card] [book card] →
   
🔘 Quick reads (Shorter than 10 minutes, not archived) — default view
   [card] [card] →

[Configure ▾]   ← user customizes which shelves appear
```

Each shelf has a descriptive subtitle that explains the filter logic. Default shelves are smart (recency + status), and the user can configure additional ones. **No "trending", no "for you" recommendations from other users' behavior.**

### 7. Empty states teach, not just announce

`/library/books` (zero books):
```
[empty center column]

Right panel: "Getting started"
  - Supported document types: explanation
  - Browser extensions: [Chrome] [Firefox] [Safari] buttons
  - Mobile apps: links
```

**Empty state shows ALL the ways to fill it**, not just one CTA. For a brand-new user this is the onboarding.

### 8. Power-user signals are everywhere

- Keyboard shortcuts in `+` menu: `A`, `U`, `Shift A`
- Sidebar collapse toggle visible
- `?` help icon bottom-right
- "Manage views" hints at custom configuration
- Right-side detail panel has tabs (Info / Notebook / Chat) — assumes you'll annotate

The product **assumes you're going to do real work here**, not just consume.

### 9. No FAB on web

There's no floating action button. The `+` lives in the sidebar header — visible but not screaming. Web pattern, not mobile pattern. Mobile is presumably different (we didn't capture).

### 10. Reader view = same chrome

When you open an item to read:

```
┌──────────┬───────────────────────┬────────────────┐
│ TOC      │ Reading content       │ Item info /    │
│ (auto-   │ (serif typography,    │ summary /      │
│  generated│  Listen button [TTS])│ metadata       │
│  from H1/H2)                     │                │
└──────────┴───────────────────────┴────────────────┘
Top bar: ← back, ↑↓ prev/next, sidebar toggle, Aa font, save/archive icons, ⋯
```

Same three columns, same nav. Switching from list to read doesn't reset your spatial model.

## TextStack — current IA (the bug)

```
Header (same for logged-out AND logged-in):
  TextStack | Books ▾ | Vocabulary | About | + Upload | 🌓 | 👤 ▾
              ↑ public catalog (SEO target)               ↑ My Library hidden here

Homepage /en (logged-in):
  Hero: "Finish the book you keep quitting" + public catalog search
  Continue Reading widget (one book)
  → user MUST think to navigate to /library
  
Library /en/library:
  Tabs: [Saved (1)]  [Uploads]
        ↑ public domain bookmarks    ↑ user's actual files
  Default tab: Saved
```

### What's structurally wrong

1. **Logged-in user sees marketing page as home.** They were authenticated; they should land in their workspace. Instead they get the same SEO-funnel page as a Google visitor.
2. **"Books" in primary nav = public catalog.** Ambiguous: my books? someone's books? It's the catalog. "My Library" is hidden behind avatar.
3. **Library tabs leak data model into UX.** Saved vs Uploads is two database concepts; for the user, both are "books in my library that came from somewhere." Default = Saved (the wrong default — uploads are the actual product).
4. **No personalized home.** No smart shelves, no "Recently added by you", no "Continue reading" surface as the landing.
5. **Add path scattered.** + button in header (Slice 01), drag-drop anywhere (Slice 02), Upload section in Library — three different patterns, no single canonical place to discover ALL ways to add content.

## Side-by-side comparison

| Dimension | Readwise Reader | TextStack today | Gap |
|---|---|---|---|
| **Logged-in landing** | Home (smart shelves of YOUR stuff) | `/en` marketing hero with public catalog search | ❌ |
| **Primary nav for personal content** | Home + Library at top of sidebar | "My Library" buried in avatar dropdown | ❌ |
| **Public catalog placement** | Tucked under `+` → Discover new docs | "Books" in primary header, equal weight to user content | ❌ |
| **Status as navigation** | INBOX / LATER / ARCHIVE tabs | None (no read/unread/archive concept) | ❌ |
| **Source as filter** | Articles/Books/PDFs/etc. as sidebar children | Saved vs Uploads as horizontal tabs | ⚠️ partial |
| **Add content entry points** | One `+` menu with 10 methods | Header button + drag-drop + Library + section | ⚠️ scattered |
| **Detail panel** | Persistent right column, even in reader | Modal or inline, not persistent | ⚠️ |
| **Smart shelves on home** | Configurable, with explained filter logic | Single "Continue Reading" widget on / | ⚠️ basic |
| **Empty state** | Teaches via right-panel "Getting started" | "No books, click +" generic | ⚠️ |
| **Tags as nav citizen** | Sibling of Articles/Books in sidebar | Recent addition (Slice 12), not in nav | ⚠️ |

## Architectural recommendations for TextStack v3

### Take from Readwise (strong copy)

1. **Logged-in landing = personal home.** When authenticated, `/en` redirects to `/en/home` (new). The public hero page is for unauthenticated visitors only.
2. **Two top-level personal surfaces:** Home (smart shelves) + Library (full grid). Both about user content. Move "Discover" (current /books catalog) to a sub-nav or tertiary entry.
3. **Status as primary axis on Library.** Currently TextStack has progress %, but no status-as-nav. Adopt: **Reading / Finished / Not started** as horizontal tabs above the grid (already in Slice 08 — formalize as primary).
4. **Source as left-sidebar filter, not tabs.** Replace "Saved" / "Uploads" tabs with sidebar children: "All", "From my uploads", "From catalog", "Tags". Tabs disappear.
5. **Single `+` menu for all content addition.** Header `+` button (Slice 01 done) becomes a menu, not a single action. Options: Upload file · Paste URL (future) · Email-to-TextStack (future) · Browser extension (future).
6. **Persistent detail panel option.** When user clicks a book card, instead of navigating, open a right-side detail panel with metadata + actions + stats (Slice 15 already partially does this). Click again or Esc to close.
7. **Smart shelves on Home.** Continue Reading + Recently added + Long reads + Finished this week + Recently saved from catalog. Default set, "Configure" hidden until user has 30+ books.

### Don't copy (deliberate divergence)

8. **Keep public catalog accessible** — it's our SEO funnel and traffic source. We can't bury it as deeply as Readwise buries Wisereads, because they don't depend on SEO traffic and we do. Instead: make it accessible via `/discover` (renamed from /books), prominent for logged-out, secondary for logged-in.
9. **Don't add "Inbox/Later" status** — books aren't articles. Reading happens over weeks, not minutes. Use Reading/Finished/Not started; "snoozed" doesn't fit.
10. **Don't add Articles/Emails/PDFs/Tweets** as content types. We're books-specific. Source filter: Uploads / Catalog. That's it.
11. **Don't require browser extension** — friction. Books don't get added from web pages the way articles do.

## Proposed v3 navigation (sketch)

### Logged-out (SEO surface — keep similar)

```

Hero:      "Finish the book you keep quitting" + catalog search
Body:      Featured public domain books, genres, authors (current /books)
Footer:    Standard
```

### Logged-in (NEW personal app)

```
                       ↑ landing  ↑ MY books  ↑ catalog          ↑ menu

  │ Sidebar      │ Status tabs:                 │
  │  All books   │ Reading | Finished | Not yet │
  │  Uploads     │                              │
  │  From catalog│ [search bar] [sort ▾]        │
  │  ───         │                              │
  │  Tags        │ [grid of book covers]        │
  │   sci-fi (3) │                              │
  │   work (5)   │                              │
  │   ───        │                              │
```

### Key URL strategy

- `/en/books/*` permanent redirects to `/en/discover/*` (preserve SEO juice).
- `/en/library/*` becomes the canonical user space.
- `/en/home` is new — for authenticated users only; redirects to `/en` (marketing) when logged out.

## Out-of-band items found during research

Things noticed in Readwise that aren't in scope but worth logging for later:

1. **Email-to-Reader pattern** — every user gets `<unique>@read.readwise.io` to forward articles. Could be powerful for TextStack: `<unique>@upload.textstack.app` for emailing EPUBs from Kindle/Calibre.
2. **AI summary on right panel ("Summarized by Ghostreader")** — they generate summaries for every saved item. We have `BookMetadataGenerator` (Ollama); could extend to per-chapter summaries.
3. **TTS button "Listen"** — visible top of every article. We have Edge TTS (`/api/tts`); should surface a "Listen to chapter" button.
4. **Pinned views in sidebar** — user-saved filtered views with custom names. Could pair with our Tags + Collections.
5. **Notebook tab in detail panel** — separate space for highlights/notes per item. We have highlights but they're not surfaced as a per-book "notebook view."

Each of these is a future slice candidate, NOT scope creep for v3 IA work.

## Risks and unknowns

1. **SEO impact of moving /books → /discover.** Permanent redirects preserve link equity; sitemap must be updated; verify no canonical-tag drift.
2. **Bot detection (per CLAUDE.md nginx config) routes crawlers to SSG.** Need to ensure logged-in redirect logic doesn't impact crawlers — bots should continue to land on `/en` marketing/SSG, not get redirected to `/en/home`.
3. **Existing users with bookmarks to `/library`** — the Library page still works at the same URL; add sidebar children gracefully.
4. **Mobile parity** — this research is desktop-only. Mobile bottom-tabs (Slice 03) was deferred; v3 mobile nav needs its own research pass.
