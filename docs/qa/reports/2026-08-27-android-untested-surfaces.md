## MQA-33 · Возврат после 33 минут в фоне

Часы на Play-образе эмулятора не сдвинуть (нет root), поэтому проверял ожиданием.
Свернул приложение **из ридера** в 15:07 на Book I, 3%, на строке «Then borrow part of winter
for thy corn». Вернул в 15:40 — 33 минуты.

**Та же книга, та же глава, тот же абзац, те же 3%, панели на месте.** Скриншоты «до» и «после»
отличаются только часами в статус-баре.

Правило `PROTECTED_ROUTE_PREFIXES` в `app/_layout.tsx` держится: сворачивание дольше получаса
не выбрасывает читателя из книги. Это ровно то, ради чего исключение и написано.

**Вторая половина правила тоже держится.** Свернул с Profile (незащищённый маршрут) в 15:41,
вернул в 16:13 — 31 минута. Приложение сбросило стек и открылось на **Library**, а не на Profile,
то есть `router.dismissAll()` + `replace('/')` отработали и корневой редирект увёл
залогиненного пользователя в библиотеку.

Итого правило подтверждено с обеих сторон: из книги не выбрасывает, с остальных экранов
возвращает к началу.

## Что работает как надо

**Закладки (MQA-22).** Полный цикл: добавил → появилась в списке → пережила `force-stop` и
холодный старт → переход по ней работает → удаление снимает и запись, и состояние кнопки.
Заявленный в [QA-004](../scenarios/QA-004-bookmarks-autosave.md) баг «bookmarks always active»
на мобильном не воспроизводится: кнопка везде показывает реальное состояние главы.

**Сессия повторения (MQA-27).** Карточка с настоящим предложением из книги → переворот →
трёхкнопочная самооценка → «Correct · New → Recognition» → итог с временем и точностью.
Проверено по API: `stage: 0 → 1`, `nextReviewAt` сдвинулся на сутки. Механизм работает.

**Удаление аккаунта (MQA-30).** Текст называет ровно то, что теряется — «uploaded books,
highlights, vocabulary, and reading history» — говорит «This cannot be undone», и CANCEL стоит
первым. Отмена действительно отменяет: аккаунт после неё жив (проверил по API).

**Собственная схема ссылок.** `textstack://book/the-aeneid` и `textstack:///en/books/the-aeneid`
(через ремап в `+not-found.tsx`) открывают книгу правильно.

**Smart session как сценарий.** План с обоснованием → карточка со сцепкой к реально прочитанной
книге → самооценка → итог с возвратом к чтению. Задумано хорошо; ломается только запись (N-6).

## Дефекты

### N-6 · P1 — Smart session не двигает интервальное повторение

Ответил «Knew» на карточке в Smart session. Экран итога: «Studied 1 · Accuracy 100%».
Состояние слова на сервере после этого:

```
stage: 0   consecutiveCorrect: 0   nextReviewAt: 16:35 (в прошлом)   dueNow: 1
```

Ничего не изменилось. Слово тут же снова предлагается как «NEW WORD».

**Контроль.** Та же карточка, отвеченная в обычной Practice, даёт `stage: 0 → 1`,
`nextReviewAt` +1 день и подпись на экране «New → Recognition». Значит SRS исправен, а
Smart session в него просто не пишет — при том что сам рапортует стопроцентную точность.

### N-7 · P1 — https-ссылки на книги открываются в браузере, а не в приложении

```
adb shell am start -d "https://textstack.app/en/books/the-aeneid"   → Chrome

adb shell pm get-app-links app.textstack.mobile
  textstack.app: 1024                  # верификация не прошла

curl https://textstack.app/.well-known/assetlinks.json
  HTTP=200,  тело: <!DOCTYPE html> …   # отдаётся SPA, а не Digital Asset Links
```

`app.json` объявляет `autoVerify: true` для `https://textstack.app/en/books*` и
`/reset-password*`. Android при проверке запрашивает `assetlinks.json`, получает HTML страницы
приложения и верификацию проваливает — отсюда состояние `1024`.

Это тот же nginx catch-all, который уже числится в STATUS как источник soft-404 для краулеров:
неизвестный путь отдаёт `index.html` с кодом 200 вместо 404.

**Что это стоит на практике:** ссылка на книгу из письма или мессенджера уводит в браузер, а не
в установленное приложение. Под это же правило подпадает `reset-password` — то есть письмо
сброса пароля тоже не откроет приложение.

### N-8 · P2 — Переключатель языка интерфейса ничего не переключает

Profile → строка «Language / EN». Тап не делает ничего.
В `packages/shared/src/i18n/index.ts`: `supportedLanguages = ['en']` — вариант ровно один.

Строка оформлена как интерактивная и стоит прямо над «Theme», где три варианта реально
работают, поэтому читается как сломанная, а не как «пока одна локаль».
(Родной язык для перевода — отдельная настройка, и она работает: список большой, выбор
сохраняется на сервер.)

### N-9 · P2 — Все ссылки-цитаты в «Ask this book» подписаны «ch.0»

Ответ содержит маркеры `[1][6][7][13][14][17]`, под ним шесть чипов — и все шесть подписаны
`ch.0`. Глава называется «Book I»; `ch.0` — внутренний индекс, попавший в интерфейс.
Сопоставить маркер с чипом нельзя. Навигация при этом исправна: тап уводит в главу.

Индексация книги перед первым вопросом заняла ~20 секунд и была честно подписана
«Indexing this book…» — это хорошо.

### N-10 · P2 — AI-экраны печатают рассуждение модели о пользователе в третьем лице

Ask the librarian:
> The user requested short Roman classics about war… No external resources were needed as the
> library had sufficient on-topic and on-constraint books.

Smart session:
> …keeps the session concise and connected to the learner's recent reading.

Приложение говорит не с человеком, а о нём, и служебным словарём («on-constraint»,
«external resources»). Два разных экрана, один источник — вывод модели уходит в интерфейс без
переписывания.

### N-11 · P2 — Хайлайты нигде не показываются с контекстом

Шит в ридере, экран Highlights и карточка review показывают только сам фрагмент. Для
однословного хайлайта это выглядит как `"in"` — вспомнить по нему невозможно.
В словаре ровно эту проблему уже починили (P2-10 из вчерашнего отчёта): там строка теперь несёт
предложение с выделенным словом. До хайлайтов правка не дошла.

### N-12 · P3 — «1 words added · 1 words reviewed»

Reading Stats → Long Term Progress. Согласование с числительным не сделано.

### N-13 · P3 — Карточка стрика повторяется на всех четырёх вкладках Stats

Overview, Books, Time, Achievements — сверху одна и та же оранжевая карточка со стриком и
тепловой картой, занимающая больше половины экрана. На «Achievements» её надо проскроллить
целиком, чтобы увидеть первое достижение. Вкладки при этом меняют только то, что под ней.

### N-14 · P3 — «Review Complete» без единого вопроса

Review хайлайтов показывает сохранённый фрагмент, книгу, главу и кнопку «Next». Ни вопроса,
ни припоминания, ни оценки — только листание. Итог тем не менее называется
«Reviewed 2 highlights».
